## Board generation

- Constants are 17 columns × 10 rows, 120 seconds, target sum 10, and daily reset hour 05:00 UTC. `dailyBoardSeed` subtracts five hours from the current time, takes the shifted UTC calendar date, parses its midnight timestamp, and truncates it to an unsigned 32-bit integer. `createSeededRandom` is an LCG with multiplier `1664525`, increment `1013904223`, and modulus `2^32`. [engine.js, constants and seed](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/engine.js#L4-L32).
- `createSolvableBoard` chooses a group count from 72–82 for the normal 170-cell board. It makes up to 40 placement attempts before throwing. Each attempt calls `createGroupSizes`, `createSumTenGroup`, then `placeGroups`. Group sizes 2–10 have weights `34,25,17,10,6,4,2,1,1`; a dynamic-programming `ways` table weights choices by how many completions exactly fill the remaining cells. [engine.js, group weights and sizing](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/engine.js#L9-L70), [generation attempts](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/engine.js#L185-L206).
- `createSumTenGroup` shuffles candidate cuts 1–9, selects `size - 1` distinct cuts, sorts them, and differences the intervals between 0 and 10. This gives positive values 1–9 summing to 10. [engine.js, partition](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/engine.js#L72-L80).
- `findPlacementCandidates` builds a 2D prefix sum of *still unassigned* cells. It enumerates rectangles with 2–10 such cells, deduplicates equivalent cell-ID sets, and stores their bounding selection and hole count. `placeGroups` chooses a group with eligible candidates, weights candidate rectangles increasingly toward holes as placement progresses, shuffles the group's values into the selected cells, marks those cells assigned, and records the selection and IDs in `solution`. The returned visible board reactivates every placed cell; playing the recorded steps in order can clear it completely because earlier placed cells have already been removed when later recorded rectangles cross them. [engine.js, candidate enumeration](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/engine.js#L82-L143), [placement](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/engine.js#L144-L183).
- This certifies **one** full solution from the initial board, not every sequence of valid moves. The repository test checks 50 deterministic seeds, values 1–9, each recorded move's sum, and complete clearing, but I inspected rather than executed the remote code or tests. [tests/engine.test.mjs](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/tests/engine.test.mjs#L16-L40), [algorithm notes](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/docs/ALGORITHM.md#L7-L23).

## Rules and round behavior in this static edition

- Pointer positions are scaled into logical grid coordinates and normalized to a rectangle. An active apple counts only if its center `(column + 0.5, row + 0.5)` is **strictly** within all four boundaries; cleared cells remain in place and contribute nothing. `inspectSelection` counts and sums all included active apples. `clearSelection` leaves the board unchanged unless the sum is exactly 10, then marks all selected apples inactive and returns their count. [app.js, coordinate mapping](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/app.js#L167-L198), [engine.js, selection and clear](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/engine.js#L211-L242).
- Score is the number of apples cleared, one point each, with 170 maximum. A round starts only after the start button; `beginRound` rebuilds the current daily seed, zeros score, and sets an absolute 120-second deadline. The 100 ms interval derives remaining time from `deadline - Date.now()`, so a delayed tick does not extend the round. Completing all 170 ends early; expiry ends it at the current score. Pause stores the remaining duration and resume creates a new deadline. [app.js, start and scoring](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/app.js#L153-L205), [pause and timer](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/app.js#L219-L229), [timer tick](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/app.js#L279-L293).
- Drag can proceed in any direction; pointer capture keeps it active across the board. Keyboard controls are arrows to move, Shift+arrows to extend, Enter to try a clear, Escape to cancel. Hint displays the next intact recorded solution step or scans the current board for any valid rectangle; it fades after 1.4 seconds. A valid move chosen outside the certified order may lead to a dead end. [app.js, hint and input](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/app.js#L207-L270), [engine.js, hint search](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/engine.js#L243-L279), [live-site guide on dead ends](https://fruitboxgame.com/#strategy).
- “New board” calls `beginRound`, so during one daily window it resets the **same** starting board. At the 05:00 UTC seed transition, the interval constructs the next board and returns to the intro state, even if a round was in progress. The personal best uses browser `localStorage` key `fruitbox-best-score` and is persisted on round completion or time expiry; a manual reset before either point does not persist that run's score. Pale only reduces saturation; Sound toggles locally synthesized Web Audio tones. [app.js, best score and audio](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/app.js#L45-L65), [controls and daily transition](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/app.js#L272-L296).

## UI and packaging

`index.html` is a single English game page: header, score/time/best strip, board with intro/paused/result overlay, feedback, controls, keyboard help, and footer. It loads `engine.js` then `app.js` as classic scripts. `engine.js` exposes pure game functions on `window.FruitBoxEngine`; `app.js` owns DOM state, event handlers, timer, local storage, hint display, and sound. `renderBoard` rebuilds cell spans, while `renderSelection` overlays a rectangle, total badge, selected-cell styling, and valid color. `styles.css` uses a fixed-aspect 17×10 CSS grid, responsive breakpoints, and CSS-drawn apples and background texture. Google Fonts are requested but have local fallbacks. [index.html](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/index.html#L1-L62), [engine export](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/engine.js#L288-L305), [app.js, render functions](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/app.js#L67-L123), [styles.css, board styles](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/styles.css#L40-L78).

The root file tree contains no package manifest, framework configuration, deployment configuration, or GitHub Actions workflow. The README says to open `index.html` directly or serve the directory with any static server; it states no build step or runtime dependency. The repository therefore does not identify a deployment target. [repository tree](https://github.com/weizixiao/fruit-box-game/tree/de7b1f59bff021d76f5138af17bed37220f7783e), [README, run instructions](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/README.md#L10-L28).

## Claimed domain versus observed site

The GitHub repository's homepage metadata and README point to [`fruitboxgame.com`](https://fruitboxgame.com/). On 29 October 2026 Singapore time, its public page showed **Classic** (fresh board each round), **Daily** (shared board until 05:00 UTC), a top-ten leaderboard, five languages, and long-form guides. The static repository has one daily board mode, English UI, and no leaderboard or server submission code. The live page says the server validates submitted moves and scores; that server implementation is not available in the inspected repository. [README](https://github.com/weizixiao/fruit-box-game/blob/de7b1f59bff021d76f5138af17bed37220f7783e/README.md#L1-L15), [live home page](https://fruitboxgame.com/).

An HTTP `HEAD` request to the domain returned `Server: cloudflare`, `x-powered-by: Next.js`, `x-opennext: 1`, `x-nextjs-prerender: 1,1`, and `x-nextjs-cache: HIT`; its HTML referenced `/_next/static/chunks/` assets. This is evidence that the observed public site is served through Cloudflare and a Next.js/OpenNext build, **not** the repository's plain `index.html` bundle. The headers do not disclose the origin infrastructure or establish which private source repository deploys it. [Observed public URL](https://fruitboxgame.com/).
